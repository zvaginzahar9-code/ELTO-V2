# ELTO

Сайт ТОО «Энергосистемы ЭЛТО» (Караганда) — завода-производителя опор
освещения, мачт и металлоконструкций.

## Overview

Редизайн действующего сайта elto.kz. Всё содержимое — каталог, характеристики,
новости, контакты — выгружено с оригинала и перенесено дословно: ни одна цифра,
формулировка и фотография не заменены. Изменена подача: сайт собран как
scroll-driven издание, где каталог и технические таблицы остаются спокойной
рабочей поверхностью, а главная страница ведёт по производству кадром.

Визуальная система «Argon»: светлый жемчужный грунт и фиолетово-розовая
световая лента аргоновой дуги, которая непрерывно проходит через всю главную
(WebGL). Опора собирается на глазах в стеклянной витрине, преимущества
сменяются крупным набором. Каждая страница ведёт к заявке: каталог, «Написать
нам», звонок, WhatsApp.

## Передача и запуск на домене заказчика

Коротко: репозиторий самодостаточен — все данные, изображения, видео и
переводы уже собраны и лежат в нём. Для запуска нужен только Node.js 20.19+.

```bash
npm ci
npm run check      # линт, типы, сборка — должно пройти без ошибок
npm run preview    # проверить собранный сайт на http://localhost:4173
```

### Вариант А — Vercel (рекомендуется, всё работает «из коробки»)

1. Vercel → Add New → Project → импортировать этот репозиторий.
   Настройки сборки берутся из `vercel.json` (`npm run build`, каталог `dist`),
   менять ничего не нужно.
2. Settings → Environment Variables (Production):
   - `SITE_ORIGIN=https://elto.kz` — адрес в sitemap, robots, canonical и превью;
   - `RESEND_API_KEY`, `LEAD_FROM`, `LEAD_TO` — отправка заявок (см. ниже).
3. Settings → Domains → добавить `elto.kz` и `www.elto.kz`; у регистратора
   домена прописать записи, которые покажет Vercel (A `76.76.21.21` для
   корня и CNAME `cname.vercel-dns.com` для www). HTTPS выдаётся сам.
4. Redeploy. Проверить: главная на трёх языках (`/ru`, `/kk`, `/en`),
   каталог, карточку изделия, отправку формы.

### Вариант Б — свой сервер (nginx и т. п.)

```bash
SITE_ORIGIN=https://elto.kz npm run build   # результат — папка dist/
```

Содержимое `dist/` копируется на сервер. Пример конфигурации со всеми
правилами (главная `home-*.html`, переход остальных адресов на `index.html`,
заголовки безопасности, кэш) — `deploy/nginx.conf`. Серверная функция
`api/lead.ts` на таком хостинге не запускается: форма это заметит и
предложит отправить заявку письмом или в WhatsApp. Чтобы письма уходили сами,
нужен обработчик `POST /api/lead` (логику можно перенести из `api/lead.ts`:
это обычная функция `Request → Response`).

### Форма заявки (Resend)

1. Завести аккаунт на resend.com, добавить домен `elto.kz` и прописать у
   регистратора DNS-записи, которые выдаст Resend (SPF/DKIM).
2. Создать API-ключ → `RESEND_API_KEY`.
3. `LEAD_FROM="ELTO <site@elto.kz>"` — адрес на проверенном домене,
   `LEAD_TO=sales@elto.kz` — куда приходят заявки.

Пока ключа нет, функция отвечает 503, а форма собирает текст заявки и
предлагает отправить его письмом или в WhatsApp — заявки не теряются.

### Старые адреса elto.kz

Ссылки старого сайта (`/ru/content/o-nas`, `/ru/content/<изделие>`,
`/ru/katalog/<раздел>`, `/ru/usefullinf` и т. д.) открывают те же материалы
нового сайта — закладки и выдача поиска продолжают работать
(`src/lib/routes.ts`, компонент `Legacy` в `src/App.tsx`).

### Что передаётся заказчику дополнительно

- PDF-каталоги — `public/docs/`;
- логотип в цвете — `public/logo_elto-1.svg`;
- выгрузка контента оригинала — `_source/content-all.json`.

Исходники фото (`_source/photos`) и видео сцен (`media-src`) в репозиторий
не входят из-за объёма; для работы сайта они не нужны — всё нужное уже
собрано в `public/`.

Дизайн-решения и их обоснование — в [DESIGN-DIRECTION.md](DESIGN-DIRECTION.md).

## Features

- каталог: 268 изделий, 52 раздела, 68 таблиц характеристик;
- поиск по названию и по маркировке из таблиц характеристик (`СТВ 9`, `ЗФ-220`), терпимый к регистру, дефисам и латинским буквам-двойникам;
- подбор по задаче объекта для тех, кто не знает маркировку — группы реальных разделов каталога;
- карточка изделия как технический лист: кадр переходит в чертёж, сводка, панель «Запросить цену / Отправить ТЗ», таблицы с закреплённой колонкой маркировки, документы, PDF-каталог раздела;
- одна форма заявки (имя, компания, контакт, сообщение, файл ТЗ) из шапки, героя, раздела, карточки, контактов и нижней панели телефона; тема подставляется сама;
- нижняя панель на телефоне: каталог, расчёт, звонок, WhatsApp;
- разделы новостей, партнёров, вакансий, фотогалереи и полезной информации;
- страница материала свёрстана как разворот издания: рубрика, крупный заголовок, полосный кадр, читаемая колонка, переход к соседнему материалу;
- страница контактов с интерактивной картой производства (тайлы, перетаскивание, зум, схема/спутник) без сторонних библиотек;
- три языка — RU, KK и EN полностью: интерфейс, каталог, карточки, таблицы, страницы, новости и политика конфиденциальности; на оригинале каталог и страницы были только по-русски, переводы сделаны для этой версии (см. «Переводы»);
- scroll-сцены на главной: искра (капля плазмы собирается в колонну), линия производства, сборка опоры с выносками в разделы каталога, взлёт над лесом колонн и город-схема;
- кадровый скраб последовательностями JPEG вместо `video.currentTime`, с отдельными кадрами 9:16 для вертикальных сцен;
- адаптив от 320 px, фиксированная навигация со сменой грунта, мобильное меню;
- поддержка `prefers-reduced-motion`: сцены не запускаются, кадры остаются на постерах, счётчики показывают конечные значения;
- изображения в трёх ширинах в webp и avif, ленивая загрузка, заданные пропорции.

## Tech Stack

- **React 19** + **TypeScript**
- **Vite** — сборка и dev-сервер
- **React Router** — маршрутизация
- **Anime.js v4** — таймлайны и проявления текста
- **Lenis** — инерционная прокрутка
- **Vercel Functions** — приём заявок (`api/lead.ts`), письмо через **Resend API**
- **sharp** — конвейер изображений (только сборочные скрипты)
- **playwright-core** — визуальный контроль и проверки (только сборочные скрипты)

Без GSAP и Three.js — ни одна сцена их не потребовала.

## Environment Variables

Все необязательны; образец — `.env.example`. Ключи задаются в настройках
проекта на Vercel и никогда не попадают в клиентский бандл.

| Переменная | Где | Зачем |
|---|---|---|
| `RESEND_API_KEY` | `api/lead.ts` | ключ Resend для отправки заявок |
| `LEAD_FROM` | `api/lead.ts` | проверенный отправитель, например `ELTO <site@elto.kz>` |
| `LEAD_TO` | `api/lead.ts` | получатель заявок, по умолчанию `sales@elto.kz` |
| `SITE_ORIGIN` | сборка | адрес сайта для `sitemap.xml`, `robots.txt` и превью, по умолчанию `https://elto.kz` |

Пока `RESEND_API_KEY` и `LEAD_FROM` не заданы, функция отвечает 503, и форма
собирает текст заявки и предлагает отправить его письмом или в WhatsApp —
заявка не теряется. Карта на странице контактов работает на публичных
тайлах без ключа.

## Deployment

Подробная инструкция — в разделе «Передача и запуск на домене заказчика».
Проект разворачивается на Vercel из репозитория: сборка `npm run build`,
каталог `dist`, функции из `api/` подхватываются автоматически. `vercel.json`
задаёт rewrites (главная на трёх языках отдаётся готовой страницей
`home-*.html`, остальные адреса — `index.html`), заголовки безопасности и кэш.

## Notes

**Пересборка данных и медиа.** Контент и изображения уже собраны и лежат в
репозитории — для запуска ничего пересобирать не нужно. Командам ниже нужны
исходники в `_source/photos` и `media-src`, которые в репозиторий не входят
из-за объёма.

| Команда | Что делает |
|---|---|
| `npm run data` | `_source/content-all.json` → `src/data/*.json` и `public/data/**`, затем наложение переводов (`scripts/build-i18n.mjs`) |
| `npm run images` | `_source/photos/*` → `public/img/{400,900,1600}/*.{webp,avif}` |
| `npm run media` | `media-src/*.mp4` → `public/media`, `public/seq`, `src/data/media.json`; план сцен, число кадров и сжатие — в начале скрипта |
| `npm run fonts` | забирает woff2 у Google Fonts → `public/fonts` и `src/styles/fonts.css` |
| `npm run prepare:data` | индекс поиска по маркировке `public/data/search.json`, `sitemap.xml`, `robots.txt` — запускается сам перед `dev` и `build` |
| `npm run shoot` | снимает сайт в настоящем браузере для визуального контроля |

**Проверки.** Запускаются по работающему серверу (`npm run dev` или
`npm run preview`); адрес переопределяется переменной `SITE_URL`.

| Команда | Что проверяет |
|---|---|
| `npm run check` | линт, типы, сборка |
| `npm run qa` | всё перечисленное ниже подряд |
| `npm run qa:responsive` | тринадцать ширин от 320 до 2560: горизонтальная прокрутка, элементы за краем, цели нажатия, ошибки консоли и сети |
| `npm run qa:overlap` | налезания: сравнивает рамки видимого текста с учётом прозрачности предков и обрезки масками |
| `npm run qa:a11y` | режим «меньше движения», alt, доступные имена, видимость фокуса |
| `npm run qa:scroll` | плавность: время кадра во время прокрутки всей главной |
| `npm run qa:perf` | вес первой загрузки, FCP, число узлов — отдельно для десктопа и телефона |
| `npm run qa:vitals` | живые FCP, LCP, CLS в браузере: какой элемент дал LCP и что сдвинуло раскладку |
| `npm run qa:lighthouse` | Lighthouse по медиане нескольких прогонов (`--desktop`, `--runs`, `--path`) |
| `npm run qa:headers` | поднимает `dist` с заголовками и rewrites из `vercel.json` и ищет нарушения CSP; с `--serve` только поднимает сервер — для Lighthouse |

**Переводы.** На elto.kz каталог, страницы и новости есть только по-русски.
Казахский и английский переводы лежат в `i18n/`: `i18n/tr/*.json` — фрагменты
текста по короткому ключу (первые 10 знаков sha1 русского фрагмента) →
`[казахский, английский]`, `i18n/kk.json` и `i18n/en.json` — короткие строки
«русский → перевод». `scripts/build-i18n.mjs` накладывает их на собранные
данные: строки, отличающиеся только маркой, переводятся одним шаблоном с `#`,
марки в английской версии пишутся латиницей (`СТВ 9-3,0` → `STV 9-3,0`).
Если на оригинале появился новый текст: `npm run data`, затем
`node scripts/build-i18n.mjs --todo` — непереведённое окажется в
`i18n/todo.txt`; переводы добавляются новым файлом в `i18n/tr/`. Подписи
интерфейса — в `src/lib/i18n.ts`.

**Первый кадр без ожидания.** Сайт рисуется на клиенте, поэтому до выполнения
бандла показывать нечего. Чтобы телефон не смотрел в пустой экран, в
`index.html` лежит стартовый кадр — графит и знак ровно на месте героя, со
встроенными стилями и встроенным SVG. Отдельного запроса он не делает, и
первая отрисовка укладывается в тот же круг по сети, что и сам документ.
Стили приложения сборка тоже кладёт внутрь документа (плагин в
`vite.config.ts`): отдельный файл стилей блокировал бы отрисовку на целый
круг. Шрифты лежат на своём домене — ссылка на Google Fonts стоила ещё двух
соединений до первого пикселя.

**Первый экран главной в HTML.** На телефоне самым поздним крупным элементом
был заголовок героя: он появлялся после загрузки бандла. Сборка кладёт рядом
с `index.html` страницы `home-ru/kk/en.html`, где вместо стартового кадра стоит
настоящая разметка героя — заголовок, кнопки, входы в разделы — из тех же
строк, что и сцена (`src/scenes/hero-copy.ts`). Сцена подхватывает этот кадр
без повторной анимации, подмены не видно.

**Заявка.** `LeadProvider` держит одну панель на нативном `<dialog>` (фокус
заперт, Esc закрывает) и открывает её из любой точки с режимом — расчёт, ТЗ,
консультация — и темой. `api/lead.ts` проверяет поля, тип и размер файла,
происхождение запроса и частоту, ловит роботов полем-приманкой и отправляет
письмо через Resend.

**Заголовки и кэш.** `vercel.json` держит CSP, защиту от кликджекинга,
`nosniff`, политику реферера и HSTS, а статике с хэшем в имени выдаёт
годовой неизменяемый кэш. Политика проверяется на собранном сайте
командой `npm run qa:headers`.

**Один тактовый генератор.** `src/motion/clock.ts` крутит единственный
`requestAnimationFrame`, в котором по очереди обновляются Lenis, движок
anime.js (`engine.useDefaultMainLoop = false`) и scroll-сцены. Поэтому
кадровый скраб, таймлайны и прокрутка не могут разойтись на кадр.

**Сцены вместо триггеров.** `src/motion/scene.ts` — реестр отрезков документа:
сцена получает свой прогресс `0→1`, и позиция `0.34` всегда значит «34 %
сцены». Закрепление кадра сделано на `position: sticky`, а не программным
пином — дешевле и без пересчёта раскладки.

**Скраб кадрами, а не видео.** `video.currentTime` по скроллу заикается на
длинном GOP. `src/components/motion/ScrollSequence.tsx` рисует декодированные
JPEG в канвас: один `drawImage` на сменившийся кадр, без seek. До загрузки
кадров и навсегда, если рендера нет, кадр держит постер.

**Вертикальная версия сцены.** Кадр 16:9 на экране 9:16 обрезается до четверти
ширины. Поэтому у искры, сборки, взлёта и города есть отдельные кадры 9:16, и
`ScrollSequence` выбирает дорожку по ширине и повороту экрана.

**Происхождение медиа.** Сцены главной сгенерированы в Google Flow (Omni 1.1
Flash) как художественные метафоры. Все изображения каталога, карточек и
материалов — настоящие фотографии и чертежи ELTO.

**Световая лента.** `src/motion/flow.ts` — WebGL2: сотни полупрозрачных нитей
по сплайну, искры и размытие по глубине, на том же тактовом генераторе.
Каждая сцена главной задаёт свою форму ленты (`src/scenes/flow-shapes.ts`),
между сценами форма перетекает. Без WebGL лента заменяется статичным фоном.

**Цвет и шрифты.** Система «Argon»: жемчуг `#F6F5FB` и surface `#FBFAFD` — грунт
главной и страниц, ночь `#120F1C` — подвал, аргон `#6A3DF0` — действие (белый текст;
как текст на светлом — `#5A2FD6`), плазма `#FF4FA3` — свет ленты.
Все пары проходят WCAG AA. Шрифты — Onest (интерфейс и
заголовки) и JetBrains Mono (данные). Знак выводится монохромно, цветом грунта;
цветная версия — `public/logo_elto-1.svg`. Обоснование и конкурентный анализ —
в `DESIGN-DIRECTION.md`.
