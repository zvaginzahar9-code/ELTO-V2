# ELTO DIGITAL EXPERIENCE — Design Direction

### 1.3 Motion reference — `авиокомпания/aether`

Next.js 16 + GSAP + Lenis, восемь scroll-driven сцен, видео сгенерировано в Google Flow (Omni 1.1 Flash).

**Что перенимаем — принципы, не дизайн:**

1. **Один тактовый генератор.** Lenis не крутит собственный rAF; он тикается внешним тикером, а обновление scroll-сцен идёт из события `scroll` Lenis. Скрабируемые канвасы и таймлайны физически не могут разойтись на кадр.
2. **Таймлайн 0→1.** Каждый scroll-таймлайн нормализуется к длительности ровно 1, чтобы позиция `0.34` означала «34 % сцены», а не 0.34 секунды.
3. **Скраб кадровой последовательностью, а не `video.currentTime`.** Seek по long-GOP файлу заикается и дерётся со скроллом. Декодированные JPEG-кадры в канвас — один `drawImage` на изменившийся кадр, без seek и без сталла.
4. **Poster-first + IntersectionObserver.** Сначала постер, кадры грузятся при приближении к вьюпорту; отсутствующий рендер никогда не оставляет пустой прямоугольник.
5. **Отдельная мобильная дорожка ассетов** (половина кадров, меньший размер, облегчённый mp4).
6. **Медиапайплайн на ffmpeg** с записью реальных счётчиков кадров в JSON — код не может разойтись с тем, что лежит на диске.
7. **Визуальный QC-стенд** на Playwright: съёмка сцены по её собственному прогрессу, а не по offset документа.

**Что не переносим:** обсидиановый void, шампань/ион палитру, Archivo/Instrument Serif, авиационный HUD, восьмичастную драматургию «фильма», Next.js, GSAP и структуру компонентов. ELTO получает собственный motion language.

## 2. Концепция

### СТАЛЬ И СВЕТ

ELTO делает то, что держит свет над страной: мачты, опоры, молниеотводы, опоры ЛЭП.
Продукция физически **вертикальна**, изготавливается из **плоского листа**, защищается **цинком** и заканчивается **светом**.

Три этих факта и есть язык сайта:

* **вертикаль** — доминирующая ось композиции;
* **лист → конус → опора** — логика производственных сцен;
* **зелёный как электрический сигнал**, а не как декоративный корпоративный цвет.

## 3. Визуальный язык

### 3.1 Двухгрунтовая система

Оригинал — светлый (белое + кремовое + зелёное). Полностью тёмный сайт перестал бы быть ELTO.
Полностью светлый — не даст кинематографичности.

Решение: **два грунта с явными правилами**.

| Грунт | Где | Зачем |
|---|---|---|
| **Графит** (`#0E1012` → `#1F242A`) | герой, производство, проекты, переходы между разделами | кинематографичность, масштаб, оцинкованная сталь читается ярче, зелёный становится энергией |
| **Бумага** (`#F4F5F0`, кремовые из темы) | каталог, карточка товара, характеристики, контакты, документы | узнаваемый ELTO, максимальная читаемость таблиц и ТТХ |

Переход между грунтами — это и есть основной ритм страницы: кино → работа → кино.

### 3.2 Токены цвета

```
--elto-green      #85C227   фирменный, из логотипа — не меняется
--elto-green-hi   #A5E33F   свечение/энергия (только свет, не заливки)
--elto-green-dim  #66862C   обводка из логотипа, бордеры на тёмном
--signal-red      #D43D29   только предупреждения/вакансии/распродажа
--graphite        #0E1012   основной тёмный грунт
--graphite-2      #15181B
--steel           #1F242A   панели на тёмном
--zinc            #C8CDD2   нейтраль: цвет горячего цинкования
--paper           #F4F5F0   светлый грунт
--cream           #F2F4DF   из темы оригинала
--ink             #1B1B1B   текст на светлом
```

### 3.3 Типографика — два семейства, не больше

* **Display / UI: Rubik** (variable 300–900, Cyrillic + казахские глифы).
  Это собственный шрифт ELTO — остаётся ради узнаваемости, но работает иначе: крупный кегль, плотный трекинг, капитель в заголовках разделов.
* **Technical: JetBrains Mono** — всё, что является данными: артикулы, мм, кг, кВ, номера разделов, счётчики, подписи к чертежам.

Разделение «слово — Rubik, число — моно» и есть инженерная интонация. Третьего шрифта нет.

### 3.4 Сетка и ритм

* Нумерация разделов `01 … 09` моноширинным — навигационный якорь.
* Вертикальный модуль: карточки товара тяготеют к формату 2:3 и 1:3 (пропорции самих опор), а не к квадрату.
* Максимальная ширина 1720, воздух по краям от 16 px на телефоне.

## 4. Motion language — пять сильных моментов

Принцип брифа: **LESS BUT BETTER**. Пять сцен несут движение; остальной сайт спокоен.

| # | Сцена | Что делает скролл | Чем оправдана |
|---|---|---|---|
| **01** | **ПОДЪЁМ** — герой | Камера идёт вверх вдоль мачты на фоне индустриального неба; кадры адресуются позицией скролла; типографика смонтирована в кадр, а не положена сверху | задаёт масштаб и сразу объясняет, что делает ELTO |
| **02** | **ИЗ ЛИСТА В ОПОРУ** — производство | Горизонтальная линия процесса: плазменная резка → гибка → сварка → горячее цинкование. Четыре видеоплиты + счётчики реальных цифр компании | **объясняет продукт** — это и есть технология ELTO |
| **03** | **СТОЙКА** — каталог | Раздел «вырастает» снизу вверх (clip-path), как поднимают опору; крупный индекс раздела; изображение живёт в полный рост | навигация по 17 разделам становится осязаемой |
| **04** | **РАЗРЕЗ** — карточка товара | Реальное фото изделия ↔ реальный заводской чертёж: вытеснение одного другим по скроллу, характеристики проявляются построчно | **объясняет продукт**; использует настоящие ассеты ELTO (у многих позиций есть и фото, и чертёж) |
| **05** | **ГЕОГРАФИЯ** — проекты и партнёры | Спокойная карта присутствия: Казахстан и СНГ, объекты, логотипы партнёров | показывает, где стоят изделия |

Микрослой (везде, но сдержанно): маскированное проявление строк (`splitText`), счётчики, подсветка активного пункта навигации, переходы между грунтами. Никакого бесконечного параллакса, вращающихся объектов и кастомного курсора.

## 5. Технические решения

### 5.1 Стек

**React 19 + Vite 7 + TypeScript + Anime.js v4 + Lenis.** Без GSAP, без Three.js.

Обоснование каждого пункта:

* **Anime.js v4** — весь интерфейсный motion: `animate`, `createTimeline`, `stagger`, `splitText` (с `wrap: 'clip'` для масок), `onScroll` для несинхронных появлений. Счётчики, карточки, навигация, переходы разделов.
* **Lenis** с `autoRaf: false` — единственный источник времени. Собственный тикер крутит `lenis.raf(t)`, из события `scroll` пересчитываются все scroll-сцены. Кадровый скраб и таймлайны на одном такте.
* **Пиннинг без GSAP** — `position: sticky` внутри высокой секции-спейсера. Дешевле ScrollTrigger по коду и по кадру, не требует пересчёта layout при пине. Поэтому GSAP не добавляется: конкретной функции, которой нет замены, не возникло.
* **WebGL не используется.** Ни один из пяти моментов его не требует; кадровый скраб и CSS-слой света дают тот же результат дешевле. Телефон не должен рендерить сцену, которую никто не просил.
* **Канвасный скрабер кадров** — собственная реализация принципа, изученного в референсе.

Маршрутизация: React Router. `/:lang` → `ru | kk | en`, далее `/catalog`, `/catalog/:category`, `/product/:slug`, `/about`, `/projects`, `/news`, `/contacts`.

### 5.2 Контент

Весь текст, названия, цифры и таблицы переносятся **дословно** из выгрузки оригинала в `src/data/*.json` на этапе сборки. Ни одна формулировка не переписывается, ни одна характеристика не сокращается.

Три языка: RU (полный, 429 страниц), KK и EN — из соответствующих разделов оригинала; там, где перевода на оригинале нет, подставляется русский, а не выдуманный перевод.

### 5.3 Ассеты

* **Фотографии продукции — реальные.** 409 оригиналов скачаны; обрабатываются в AVIF/WebP в трёх размерах, фон выравнивается, продукт не подменяется.
* **Генерируемое видео (Google Flow, Omni Flash)** отвечает только за **среду и атмосферу**: индустриальное небо, искры плазмы, ванна цинкования, ночная трасса, подстанция. Изделия в кадре — настоящие фотографии ELTO. AI не рисует продукцию вместо реальных изделий.
* **Корпоративный ролик** оригинала (`2lW6Hn6otPU`) сохраняется в разделе о компании.
* Видео скачивается в максимальном доступном качестве и только потом пережимается для web (h264 faststart, короткий GOP; отдельная мобильная дорожка).

### 5.4 Производительность

Бюджет: первая отрисовка — постер, не пустой прямоугольник. Кадровые последовательности грузятся по IntersectionObserver с запасом 150 %. Мобильная дорожка — половина кадров. Анимируются только `transform`, `opacity`, `clip-path`. Маршруты разделены по коду. `prefers-reduced-motion` отключает скраб и оставляет статичные постеры.
